1 · EDA & Data Quality (StayEase Booking Analytics)

Goal: act as a junior data analyst. Investigate hotel booking data, find data-quality issues, clean it, find patterns (cancellations, seasons, pricing, channels) and recommend business actions. No fixed procedure: every decision must be justified with evidence.

Dataset columns (examples)

hotel_type, booking_status, advance_booking_days, arrival_month, weekend_nights, weekday_nights, num_adults/children/infants, meal_plan, booking_channel, is_repeated_guest, deposit_type, travel_agent_id, avg_daily_rate, reservation_status, derived: total_stay_nights, total_guests, booking_season, is_long_stay.

Attribute types

TypeMeaningExample
Nominalcategories, no orderhotel_type, booking_channel, guest_country
Ordinalordered categoriesarrival_month, booking_season
Binarytwo valuesis_repeated_guest, family_booking
Discrete numericcountsnum_adults, special_requests
Continuous numericany real valueavg_daily_rate

Data-quality issues → treatment

  • Missing numeric: median if skewed or outliers, mean if symmetric. Missing categorical: mode, or an "Unknown" category.
  • Structurally missing (e.g. travel_agent_id blank = no agent): fill with "No Agent". Don't drop the rows.
  • Duplicates: df.duplicated().sum() then drop_duplicates().
  • Outliers: IQR rule. Outside [Q1 − 1.5·IQR, Q3 + 1.5·IQR]. Cap, transform (log) or investigate.
  • Invalid/inconsistent: 0 guests, negative rate, reserved ≠ assigned room. Check with domain logic.
  • Leakage: reservation_status already encodes cancellation. Never use it to predict booking_status.

Pandas toolkit

df.shape df.info() df.describe() df.isnull().sum() df.duplicated().sum() df['col'].value_counts() df.groupby('channel')['booking_status'].mean() df.corr(numeric_only=True)

Which plot?

  • 1 numeric → histogram / KDE / box plot. 1 categorical → bar / countplot.
  • numeric vs numeric → scatter; many numerics → correlation heatmap.
  • category vs category (e.g. channel vs cancelled) → grouped / stacked bar (hue=).
  • trend over months → line chart. numeric by category → box / violin plot.

Statistics

  • Mean > median → right skew; mean < median → left skew.
  • Pearson r ∈ [−1, 1] measures linear association only. Correlation ≠ causation.
  • Box plot = min, Q1, median, Q3, max (five-number summary) + outliers.

Deliverables: notebook, a 5–8 page analyst report (exec summary → recommendations → limitations), a decision log (Decision | Reason | Evidence | Alternative) and a visualization portfolio.

2 · PyTorch Basics: Tensors

Tensors are multi-dimensional arrays like NumPy's, but with GPU support and autograd. They live on the CPU by default.

Creation

torch.tensor([[1,2],[3,4]]) # from data → dtype int64 torch.from_numpy(np_arr) # SHARES memory with numpy torch.ones_like(x) / rand_like(x, dtype=torch.float) # keeps shape (and dtype unless overridden) torch.ones(2,3) torch.zeros(2,3) torch.rand(2,3) # rand: uniform [0,1), float32 torch.empty(2,3) # uninitialised garbage values torch.manual_seed(1789) # reproducible random numbers

Attributes

.shape (torch.Size), .dtype (int8/16/32/64, float32/64, bool…), .device (cpu / cuda / mps). Move with t.to("cuda"). On Apple Silicon use mps.

Indexing & ops

  • t[0] first row, t[:,0] first column, t[:,-1] last column, t[:,1]=0 sets column 2.
  • * element-wise, @ / torch.matmul matrix multiply.
  • torch.clamp(a,-0.5,0.5) clips values. abs, ceil, floor, sin, asin.
  • Reductions: max, mean, std (unbiased, divides by n−1), prod, unique. .item() → Python number.
  • torch.eq(a,b) → bool tensor. bitwise_xor([1,5,11],[2,7,10]) = [3,2,1].

Broadcasting rules (compare from the LAST dim)

Each pair of dims must be equal, or one of them is 1, or one is missing. Example: (4,3,2) works with (3,2), (4,1,2) and (1,3,2); it fails with (2,3).

Shape manipulation

torch.reshape(a,(2,2)) x.view(1,256) # 16x16 → 1x256 b.unsqueeze(0) (56,56) → (1,56,56) # add a dim (batch) d.squeeze(0) (1,20) → (20,) # remove a size-1 dim torch.cat((x,y,z), dim=0) three (2,3) → (6,3)

In-place & copies

  • An underscore suffix means in-place: a.add_(b), torch.sin_(b), b.mul_(b).
  • out= writes into an existing tensor (c is d is True, same id).
  • b = a is just another label (changes show in both). b = a.clone() is a real copy.
  • from_numpy / .numpy() share memory, so changing one changes the other.
Trap: torch.std([[1,2],[3,4]]) = 1.291 (sample std), not 1.118. The default dtype from Python ints is int64 and from floats is float32.

3 · Exploratory Decision Trees (Breast Cancer Wisconsin)

Data: load_breast_cancer(): 569 samples, 30 features (10 nucleus measurements × {mean, standard error, worst}). Target 0 = malignant (212, 37.3%), 1 = benign (357, 62.7%). Always-benign baseline ≈ 63% accuracy. Split 80/20, stratify=y, random_state=42.

Impurity

Gini = 1 − Σ pᵢ² (CART, sklearn default) Entropy = − Σ pᵢ log₂ pᵢ (ID3 / C4.5, information gain) Info Gain = H(parent) − Σ (nₖ/n)·H(childₖ) 50/50 node: Gini 0.5, Entropy 1 | pure node: both 0 (0.25,0.75): Gini 0.375, Entropy 0.811

sklearn is CART-based, and entropy is just an option via criterion. In the lab both gave 0.9123 accuracy but different depths (7 vs 6), so they behave similarly but are not identical.

Depth sweep (max_depth 1 → 20)

Train accuracy climbs to 100%. Test accuracy peaks at a moderate depth and then plateaus or drops. The gap is overfitting. Depth 1 (a stump) underfits.

Pruning

  • max_depth = pre-pruning (early stopping).
  • ccp_alpha = post-pruning (cost-complexity): grow the full tree, then trim. α = 0 means no pruning; larger α means a smaller tree, down to a single leaf.
  • clf.cost_complexity_pruning_path(X_train, y_train).ccp_alphas gives the candidate alphas (drop the last one, which is the single-node tree).

Evaluation & selection

  • Confusion matrix: in cancer, a false negative (missed malignant) is the costly error. Accuracy alone hides this.
  • GridSearchCV (5-fold) over criterion × max_depth. CV averages over folds, so it is more trustworthy than the best score on a single test split (which can be luck).
  • Feature importance = total impurity decrease, weighted by the samples reaching the node. The root feature dominates.
  • radius, perimeter and area are highly correlated (they all measure size). Trees need no scaling.

4 · Model Selection: Decision Tree vs kNN (Week 4)

Tune hyperparameters three ways (manual grid search, GridSearchCV, RandomizedSearchCV) on at least 2 datasets: Wine Quality (good if quality > 5), HR Attrition (get_dummies, drop_first=True), Banknote (4 features), QSAR Biodegradation (RB = 1). Split 70/30, stratified.

Pipeline

Pipeline([('scaler', StandardScaler()), ('feature_selection', SelectKBest(f_classif, k=...)), ('classifier', KNeighborsClassifier())]) param_grid = {'scaler': [StandardScaler(), MinMaxScaler()], 'feature_selection__k': [...], # ≤ n_features! 'classifier__n_neighbors': [...]} # step__param (double underscore)
  • A pipeline prevents leakage: the scaler and selector are fit only on the training folds.
  • f_classif = ANOVA F-test score per feature.
  • StandardScaler → mean 0, std 1. MinMaxScaler → [0, 1].

Three parts

  1. Manual: itertools.product over the grid. For each combination, 5-fold StratifiedKFold: fit on the fold, take predict_proba[:,1], compute ROC AUC, average. Keep the best, then refit on the full train set.
  2. GridSearchCV(pipe, grid, scoring='roc_auc', cv=StratifiedKFold(5), n_jobs=-1). Time it. Outputs best_estimator_ (refit on all train), best_params_, best_score_ (mean CV score).
  3. RandomizedSearchCV with n_iter=10 and scipy.stats.randint distributions. Faster, may miss the optimum.

Total fits = combinations × folds. Example: 2×3×4 = 24 combinations × 5 folds = 120.

kNN vs Decision Tree

  • kNN is distance-based, so it is very sensitive to scaling. It is a non-parametric lazy learner. Small k overfits, large k underfits.
  • Decision trees use threshold splits, so they are scale-invariant.

Voting

Hard voting = majority of labels. Soft voting = average the probabilities. In the manual vote, 1 if mean(votes) > 0.5 else 0, so a 1–1 tie between two models becomes 0.

ROC = TPR vs FPR across thresholds. AUC 0.5 = random, 1 = perfect.

5 · Linear vs Logistic Regression (Week 5)

Part 1: toy data (hours studied → pass)

20 points in x ∈ [0, 10] with y = 1 if x > 5, plus an outlier at x = 50, y = 1.

  • Linear regression: the outlier pulls the line, so the 0.5 crossing shifts and normal points get misclassified. Outputs also go outside [0, 1].
  • Logistic regression (random_state=42): the sigmoid is bounded in (0, 1), and the boundary stays near x = 5. It is robust. Use predict_proba(X)[:,1].
σ(z) = 1 / (1 + e^(−z)) σ(0) = 0.5 P(y=1|x) = σ(w·x + b) log-odds log(p/(1−p)) = w·x + b (linear boundary) Loss = log-loss / binary cross-entropy = −[y log p + (1−y) log(1−p)] odds = p/(1−p) (p = 0.8 → odds 4)

sklearn default: L2 penalty, C = 1.0 (C = 1/regularisation strength).

Part 2: Wine Quality pipeline

Pipeline([('scaler', StandardScaler()), ('feature_selection', SelectKBest(f_classif, k=8)), ('classifier', LogisticRegression(random_state=42))])

Thresholds 0.3 / 0.5 / 0.7

  • Lower threshold → more predicted positives → recall ↑, precision ↓.
  • Higher threshold → fewer positives → precision ↑, recall ↓.
  • Threshold 0 → recall = 1. zero_division=0 handles the case where nothing is predicted positive.

6 · Neural Network from Scratch (NumPy, Week 6)

Approximate a noisy polynomial. Type = last 3 SRN digits % 5: quadratic, cubic, quartic, cubic + sin, or cubic + inverse. Architecture = % 4: (64,64, lr 0.001), (32,72, lr 0.005), (72,32, lr 0.001) or (96,96, lr 0.003). 100,000 samples, x ∈ [−100, 100], split 80/20. Both x and y are standardised (otherwise huge values make gradients explode). Predictions are converted back with inverse_transform.

Architecture

Input(1) → Hidden1 (ReLU) → Hidden2 (ReLU) → Output(1) with a linear output (regression). Without activations the whole network collapses to one linear model.

relu(z) = max(0, z) relu'(z) = 1 if z > 0 else 0 MSE = mean((y − ŷ)²) Xavier: W ~ N(0, sqrt(2/(fan_in + fan_out))), biases = 0 W1:(1,h1) W2:(h1,h2) W3:(h2,1) Params (1→64→64→1) = 128 + 4160 + 65 = 4353

Forward / backward

z1 = X@W1 + b1; a1 = relu(z1) z2 = a1@W2 + b2; a2 = relu(z2) z3 = a2@W3 + b3 (= ŷ) dŷ = 2(ŷ − y)/m dW3 = a2.T @ dŷ db3 = sum(dŷ, axis=0) da2 = dŷ @ W3.T dz2 = da2 * relu'(z2) dW2 = a1.T @ dz2 da1 = dz2 @ W2.T dz1 = da1 * relu'(z1) dW1 = X.T @ dz1 W ← W − lr·dW (gradient descent)
  • Training is full-batch: every epoch uses the whole X_train. Early stopping with patience 10 stops after 10 epochs without test-loss improvement and keeps the best weights.
  • Learning rate too high → loss oscillates or diverges. Too low → slow.
  • Too-small initial weights → vanishing gradients; too large → exploding. ReLU reduces vanishing gradients (sigmoid's max gradient is 0.25). Dying ReLU = a neuron that always outputs 0 and never learns again.
  • R² = 1 − SS_res/SS_tot (1 = perfect, 0 = no better than the mean).
  • Part B: run 4 experiments changing lr / batch size / epochs / activation, and record them in a results table.

7 · Naive Bayes: From Scratch to Bayes Optimal

Task: PubMed 20k RCT. Classify each abstract sentence as BACKGROUND, OBJECTIVE, METHODS, RESULTS or CONCLUSIONS. There are 180,040 training sentences, the classes are imbalanced, and the data comes pre-split into train, dev and test.

Model

ĉ = argmax_c P(c)·Π P(wᵢ|c)^xᵢ (P(x) dropped: same for all classes) log space: score(c) = log P(c) + Σ xᵢ log P(wᵢ|c) P(c) = N_c / N (counts DOCUMENTS, not words) P(w|c) = (count(w,c) + α) / (Σ count(·,c) + α·V) V = vocab size scores = X @ feature_log_prob_.T + class_log_prior_ (no loops)
  • Naive assumption: words are conditionally independent given the class. It is false, but NB still classifies well because only the ranking (argmax) matters. Its probabilities are overconfident.
  • Log space avoids underflow (25 words ≈ 10⁻¹²⁵ → 0.0). log is monotone, so the argmax is unchanged.
  • Smoothing: without it, an unseen word gives P = 0, log = −∞, and the class is eliminated. α = 1 is Laplace; α < 1 is Lidstone. Forgetting the αV term gives an invalid distribution, but accuracy may barely change.
  • Verification: match sklearn MultinomialNB (class_log_prior_, feature_log_prob_) to a max difference < 1e-10. Check this before looking at accuracy.
  • CountVectorizer(lowercase=True, strip_accents="unicode", stop_words="english", ngram_range=(1,1), min_df=2). Fit on train only; transform dev and test.

Experiments

  • α sweep [0.01, 0.1, 0.5, 1, 2] on dev using macro-F1, plotted on a log x-axis. Test is used only after α is fixed.
  • TF-IDF = tf × log(N/df). Very common words get weight ≈ 0. TF-IDF is not counts, so using it with multinomial NB is justified empirically, not by theory. ngram_range=(1,2) adds bigrams like "double blind".
  • GridSearchCV (3-fold, macro-F1) over n-grams × α.

Bayes Optimal Classifier (Part C)

P(c|x,D) = Σ_h P(c|x,h)·P(h|D) uniform prior ⇒ P(h|D) ∝ P(D_held|h)
  • No classifier with the same hypothesis space and prior can do better on average. It can't be computed exactly because H is infinite, so the lab approximates it with 4 models: NB, LR, DT and RF.
  • Weights = softmax of the mean held-out log-likelihood. Clip probabilities first (log 0 = −∞) and subtract the max before exp (to avoid overflow). Using the summed log-likelihood instead gives near one-hot weights.
  • VotingClassifier(voting="soft", weights=posterior_weights), compared against each individual model.

Metric: macro-F1 = unweighted mean of the per-class F1 scores, so rare classes count equally. In a row-normalised confusion matrix, the diagonal is recall. Protocol: train fits, dev selects, test is scored once.

8 · Support Vector Machines (Week 10)

SVM finds the maximum-margin hyperplane w·x + b = 0. Margin width = 2/‖w‖. Support vectors are the points on or inside the margin; only they define the boundary. Loss = hinge, max(0, 1 − y·f(x)).

Kernels (kernel trick: inner products in a higher-dimensional space without mapping explicitly)

KernelFormulaBoundary
linearx·x'straight line
rbf (SVC default)exp(−γ‖x−x'‖²)flexible curves/circles; high γ → wiggly, overfits
poly (degree = 3 default)(γ x·x' + r)^dpolynomial curve

The three parts

  1. Moons: make_moons(n_samples=500, noise=0.2, random_state=42), split 70/30, StandardScaler. The data is non-linear, so Linear does worst and RBF fits the shape most naturally.
  2. Banknote: only variance and skewness are used (so the boundary can be plotted in 2-D), stratified split. The data is nearly linearly separable, so linear and RBF do well and poly underperforms (its extra curvature doesn't fit the data's shape).
  3. Hard vs soft margin: make_blobs(100, centers=2, cluster_std=0.6) plus 2 outliers, with SVC(kernel='linear', C=…, random_state=42).

9 · Hidden Markov Models (Week 11)

λ = (A, B, π). Hidden states can't be seen; we see observations emitted by them. Markov property: the next state depends only on the current one. Rows of A and of B each sum to 1.

Lab variable names (weather HMM)

avocadotransition matrix Akangarooemission matrix B
bubbleguminitial distribution πmushroomhidden states (6 weathers)
spaceshipobservation symbolscheese / jellybean# states / # observations
skateboardinput observation sequencerat / mouseViterbi output / expected

States: Clear Skies, Partly Cloudy, Overcast, Rainy, Stormy, Snowy. Observations: Temperature Rise, Drop in Barometric Pressure, High Wind Speed, Increased Humidity, Thunder Heard, Heavy Snowfall.

Algorithms (dynamic programming, O(N²T) instead of brute-force N^T)

Init (both): δ₁(i) = πᵢ · bᵢ(o₁) Forward: αₜ(j) = [Σᵢ αₜ₋₁(i)·aᵢⱼ] · bⱼ(oₜ) P(O|λ) = Σᵢ α_T(i) → likelihood Viterbi: δₜ(j) = maxᵢ[δₜ₋₁(i)·aᵢⱼ] · bⱼ(oₜ) + backpointer = argmax → best path end: argmax δ_T, then follow backpointers back to t = 1

Viterbi = max, Forward = sum. For long sequences, use log probabilities to avoid underflow.

Test: [Temp Rise, Humidity, High Wind, Pressure Drop] → [Clear Skies, Rainy, Overcast, Clear Skies]. (δ₁: Clear Skies = 0.2 × 0.4 = 0.08 is the largest.) Implement with PyTorch, using DP only and no hard-coding. Run python3 test.py --ID CAMPUS_SECTION_SRN_Week11.

hmmlearn demo (robot)

  • States: Charging, Navigating, Exploring. Observations: idle, move, scan. π = [0.3, 0.4, 0.3]; A[Charging→Navigating] = 0.8.
  • hmm.MultinomialHMM(n_components=3, n_iter=50, init_params='') uses the parameters you set manually. init_params='ste' auto-initialises start, transition and emission.
  • .fit() learns the parameters with Baum–Welch (EM). .decode() returns (log prob, Viterbi states).
  • Example: P(o₁ = scan) = Σ πᵢ·bᵢ(scan) = 0.3·0.33 + 0.4·0.7 + 0.3·0.44 = 0.511.

10 · CNN: Rock, Paper, Scissors (Week 14)

Kaggle drgfreeman/rockpaperscissors, about 2,000+ images. ImageFolder labels images from the folder names, sorted: ['paper', 'rock', 'scissors'].

device = torch.device("cuda" if torch.cuda.is_available() else "cpu") transform = Compose([Resize((128,128)), ToTensor(), Normalize((0.5,)*3, (0.5,)*3)]) # → [-1, 1] random_split 80/20; DataLoader(batch_size=32, shuffle=True for train, False for test) conv: [Conv2d(3→16,k3,p1), ReLU, MaxPool(2)] 128→64 [Conv2d(16→32,k3,p1), ReLU, MaxPool(2)] 64→32 [Conv2d(32→64,k3,p1), ReLU, MaxPool(2)] 32→16 fc: Flatten → Linear(64·16·16 = 16384 → 256) → ReLU → Dropout(0.3) → Linear(256 → 3) criterion = nn.CrossEntropyLoss(); optimizer = Adam(lr=0.001); EPOCHS = 10
  • Output size = (W − K + 2P)/S + 1. With k = 3, p = 1, s = 1 the size is unchanged ("same" padding).
  • Conv params = out × (in × k × k) + out. Conv2d(3,16,3) = 432 + 16 = 448. Pooling has no parameters.
  • ToTensor: HWC 0–255 → CHW 0–1. Input has 3 channels (RGB).
  • No softmax at the end: CrossEntropyLoss takes raw logits (it applies log-softmax internally).
  • Training step: zero_grad → outputs = model(x) → loss = criterion(outputs, y) → loss.backward() → optimizer.step(). zero_grad is needed because gradients accumulate.
  • Eval: model.eval() turns off dropout. with torch.no_grad() stops gradient tracking. _, pred = torch.max(outputs, 1) gives the class indices.
  • Single image: transform(img).unsqueeze(0) adds the batch dimension (1, 3, 128, 128).
  • Batches per epoch = ceil(train / 32), e.g. 1750 → 55.
  • CNNs have fewer parameters thanks to weight sharing and local connectivity. To improve: data augmentation, more regularisation, BatchNorm, more epochs with validation.

★ Metrics & General Cheat-Sheet

Confusion matrix (sklearn): [[TN, FP], [FN, TP]] rows = actual, cols = predicted Accuracy = (TP+TN)/total Precision = TP/(TP+FP) "of predicted positives, how many are right" Recall = TP/(TP+FN) = TPR "of actual positives, how many found" FPR = FP/(FP+TN) F1 = 2PR/(P+R) (harmonic mean) Macro-F1 = mean of per-class F1 ROC: TPR vs FPR; AUC 0.5 = random, 1 = perfect
  • Overfitting = high train score, low test score (deep trees, large C, high γ, small k). Underfitting = both low.
  • Data leakage: fit scalers, vectorizers and selectors on train only, and use a Pipeline inside CV.
  • Stratify to keep class ratios in the splits/folds. random_state=42 makes results reproducible.
  • Scale-sensitive: kNN, SVM, LR, NN. Scale-invariant: decision trees.
  • Train / validation (dev) / test: choose hyperparameters on validation, report test once.
  • Imbalanced data: accuracy misleads, so use precision, recall, F1 and the confusion matrix.
